# 插件 README 中文翻译指南

本文是 `data/readmes-zh/` 下全部译文的统一规范。目标:**细致、完整、忠实**,
让读者只看中文就能完全理解该插件,而不是摘要或意译。

源文件: `~/.oh-my-zsh/plugins/<插件名>/README.md`(oh-my-zsh 官方仓库)。
译文文件: `data/readmes-zh/<插件名>.md`(文件名与插件名完全一致)。

## 铁律

1. **完整翻译,不许删节**:源 README 的每一个段落、每一个列表项、每一条提示,
   都必须翻译成中文。不许概括、缩写、合并或跳过任何内容。
2. **结构一一对应**:标题层级与数量、列表项数、表格行数、链接数量必须与源文一致
   (唯一例外见「样板启用段」)。校验脚本会逐项核对。
3. **代码块原样保留**:围栏代码块(``` 包裹)内容一字不改,包括注释。
   代码块紧邻的英文说明文字必须翻译。
4. **命令与标识符不译**:命令、别名、函数名、路径、变量、配置键、插件名、
   专有名词(docker、kubectl、Homebrew、Ansible…)保持英文原文。
5. **不许添加源文没有的内容**:不写译注、不补充自己的用法、不加「译者按」。

## 具体规则

### 样板启用段(唯一允许的差异)

源文里下面的样板段(措辞可能略有变化,但特征是 "add ... to the plugins array"):

```markdown
To use it, add `xxx` to the plugins array in your zshrc file:
...示例代码块...
```

整段(含紧跟的示例代码块)替换为一行:

```markdown
✅ 启用方式:把「xxx」加入 zshrc 的 plugins 数组(可用 omz-pm 一键完成)。
```

其余任何段落都不允许整段删除。若启用说明与其他内容写在同一段,只替换启用措辞,
保留其余句子的翻译。

### 标题

- `## Usage` → `## 用法`;`## Aliases` → `## 别名`;`## Options` → `## 选项` 等。
- 词典:`Usage→用法, Options→选项, Aliases→别名, Settings→设置, Configuration→配置,
  Installation→安装, Requirements→依赖要求, Examples→示例, Features→特性,
  Key binding→键位绑定, Troubleshooting→故障排查, Notes→注意, FAQ→常见问题,
  Contributing→参与贡献, License→许可证, Credits→致谢, See also→另见`。
- 词典未覆盖的标题按含义翻译;纯专有名词(如 `## Terraform`)保留。
- 首行 `# <plugin>` 标题保留插件名(专有名词,不译;可加「插件」等词,如 `# Docker 插件`)。

### 表格

- 表头行翻译:`Alias→别名, Command→命令, Description→说明, Option→选项,
  Variable→变量, Function→函数, Default→默认值`。
- 别名/命令/键位等数据列**原样保留**,一格不动。
- 说明列的英文句子完整翻译成中文,逐行对应,不许漏行。

### 行内代码与链接

- 行内代码 `` `...` `` 原样保留;代码外面的说明文字翻译。
- 链接:URL 不动,链接文字翻译,如 `[enable it](url)` → `[启用它](url)`。
- 裸 URL 保留原样。
- `<kbd>esc</kbd>`、`<Tab>` 等 HTML 标签原样保留。

### 强调标记

`**粗体**`、`_斜体_`、`> 引用`、列表符号(-、*、数字)等 markdown 语法结构与源文一致。

## 文风

- 简体中文,书面但自然,技术文档口吻;不生硬直译。
- 中英文/数字之间加一个半角空格(与 data/translations.json 现有文风一致)。
- 标点用中文全角(句号、逗号、顿号、引号「」);代码、命令内部保持半角。
- 命令输出里无法翻译的内容(如 `-su: Permission denied`)保留原文,这是输出不是文档。
- 长句可以拆,但语义不得增删。
